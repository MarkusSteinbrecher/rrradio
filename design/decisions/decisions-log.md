# rrradio — Architecture Decisions Log

Audit-tagged choices that should not be re-debated without a reason. Each entry is a single decision; promote to a proper ADR (`design/decisions/NNN-slug.md`) when one needs deeper context, alternatives, or consequences captured.

## Catalog format

YAML source, JSON build artifact. `public/stations.json` is committed (not gitignored) so GitHub Pages serves a working file even if the build step fails.

## Stream variants + catalog collapse → [ADR 001](001-stream-variants-and-catalog-collapse.md)

Same-station rows (bitrate/codec variants of one broadcast, e.g. FM4 192k + 128k) collapse at build time into one published station carrying an ordered `streams[]` (best→worst, `streamUrl` = best). Additive schema — v1 clients ignore `streams` and play `streamUrl`. Collapse is **conservative**: only rows sharing a stream path (exact URL or fingerprint) merge — never "same brand name" (would hide distinct sub-channels) and never the raw `dedupe.json` grouping (over-merges). Curators steer via `data/sources/catalog-dedupe-overrides.yaml`; every merge is audited in `public/dedup-report.json`. Listener-facing best/data selection is specified but client-side Planned. See the ADR for context, alternatives, consequences.

## No autogenerated docs

Status is implicit in YAML. Avoid generating prose from the catalog.

## No backend

Sync across devices, user submissions, etc. need a real backend (Firebase / Supabase) — out of scope. Static site stays static.

## iTunes Search for cover art

iTunes Search is the cover-art enrichment fallback; not Shazam, not Spotify (both need backends or paid keys).

## Locked stations

Apple Music, Spotify, etc. are recorded in YAML with `status: not-public` so we don't keep rediscovering they don't work.

## HTTPS-only catalog (audit #71)

`tools/check-catalog.mjs` fails CI on any `http://` `streamUrl` not on a per-station allowlist. Opt out with `httpAllowed: true` in `data/stations.yaml` and a comment explaining why HTTPS isn't available. iOS routes those hosts via per-host `NSExceptionDomains` in `ios/project.yml` — App Review will reject `NSAllowsArbitraryLoads`. Web add-custom form rejects `http://` up-front (mixed-content blocks playback anyway).

## Strict CSP via `<meta>` + per-page sha256 hashes (audit #75)

`index.html` ships with `'unsafe-inline'` in `script-src` so dev works; `tools/build-station-pages.mjs` rewrites every emitted page's meta-CSP to drop `'unsafe-inline'` and add `'sha256-<hash>'` entries for the inline JSON-LD blocks. Playwright e2e asserts the post-build form. **Never add `'unsafe-eval'`.** The dynamic-text DOM helpers (`statusLine` / `emptyState` in `src/empty.ts`) use `textContent` so an `Error.message` carrying markup can't smuggle DOM. URL safety lives in `src/url.ts` (http(s) allowlist).

## Privacy-preserving runtime errors (audit #76)

All caught exceptions, unhandled rejections, catalog-load failures, Worker fetch failures, and stream errors emit `error: <category>` events to GoatCounter via `src/errors.ts`. No new third-party endpoint; the existing dashboard "errors" panel surfaces them alongside per-station play errors. Build version (short SHA + ISO date) is injected by Vite `define` and included in every error title for regression-to-commit traceability. Stack traces and PII are deliberately not captured — see `public/privacy.html`.

## Single typed Worker base URL (audit #66)

Browser code imports from `src/config.ts` (`STATS_WORKER_BASE`, `STATS_PROXY`, `STATS_BBC_PROXY`); never hardcode the workers.dev URL anywhere else. Local dev against `wrangler dev` via `VITE_STATS_WORKER_BASE=http://localhost:8787` in `.env.local`. The standalone `public/dashboard.html` is the one exception (it's a self-contained static page outside the Vite build).

## Wake-to-radio architecture

- **Silent bed** (`/silence.m4a`, looped) keeps the iOS audio session alive between arm and fire.
- **Sidecar prime** at arm time grants iOS a fresh user-activation token on a separate audio element so `swap()` at fire time can adopt that element instead of fighting the silent-bed element's stale gesture grant.
- **`swap()`** never calls `audio.removeAttribute('src') + audio.load()` — those end the iOS media-playback session.
- **Disarm restores currentNP** to the originally-armed station (paused) via `player.setStation()` so the user doesn't lose their NP context after cancelling an alarm.
- **Wake editor lives inline on the NP screen** (the `.np-wake-pane`); there's no slide-up sheet. Tapping the alarm icon at the bottom of NP controls toggles it.

## Render extractions go through the harness (audit #77)

When a DOM-touching function in `main.ts` reaches "second time I'm copying refs" or "want to add a unit test", extract it into a refs-based module under `src/render-*.ts` with a typed `*Refs` interface and a fragment in `src/render-test-harness.ts`. See `docs/testing.md` for the pattern.

## Unified station-health record (2026-06-10)

All automated catalog checks write per-station verdicts into one committed artifact, `public/station-health.json`, through `tools/lib/health-record.mjs` — verdict + transition date per facet (`stream`, `https`, `icy`, `metadata`, `fetcher`, `program`, `logo`, `homepage`, `drift`, `duplicate`), with last-run/coverage per facet in a `runs` header. One station per line, sorted, transitions-only updates, so the weekly refresh diffs small (the git-bloat lesson). `tools/health-probe.mjs` (concurrent, scoped, merge-on-partial-run) replaces the duplicated sequential probes in `validate-catalog.mjs` + `analyze.mjs`, which could no longer finish a 24k-station sweep inside a CI job — catalog-watch had failed five consecutive weeks (probe volume, then a Node 22/npm 11 lockfile mismatch). The station tracker's Health tab is the primary reader; the admin dashboard keeps `station-status.json`, now problems-only. Full spec: `docs/station-health.md`.

## No code-graph database for documentation (2026-05-31)

Evaluated codebase→graph-DB tools — Blarify, Potpie, FalkorDB code-graph, code-graph-rag, Sourcegraph precise-nav, GitHub stack-graphs, Glean — plus the two Swift-capable ones, CodeQL and Joern. **Decision: skip.** The generic "repo → knowledge graph" tools don't support Swift at all; CodeQL/Joern do but are security/static-analysis platforms (macOS/JVM, GHAS-licensed for private repos), not documentation generators; and the accurate Swift symbol/reference graph already exists for free from the compiler IndexStore (+ Periphery / SourceKit-LSP). Cross-platform parity is a *contract* problem — solved by the markdown spec under `docs/spec/` (including the `contracts/` tier), not a call graph. A code graph would pay off only for a large polyglot monorepo, cross-service impact analysis, or RAG over code too big for a context window — none of which is one mid-size SwiftUI app. Escape hatch if code-level questions bite: run `periphery` against the iOS IndexStore, not a graph DB. Full rationale: rrradio-ios `internal/design/2026-05-31-cross-platform-spec-plan.md` §9.

## Disclose the rrradio-operated IP-bearing flows on store privacy labels (2026-06-13)

The native apps make IP-bearing calls to first-party `stats.rrradio.org` (region resolution, Stats-sheet GETs, the CORS/ICY + BBC proxies, broken-station report + receipt polling — `privacy-data-boundaries.md` matrix rows 2–6 and 15). Some fire silently while sibling Settings copy frames the app as on-device. **Decision: disclose** — keep `stats.rrradio.org` and fully declare these flows on the App Store privacy nutrition label and the Play Store Data Safety form, rather than gating them behind consent or removing them. Codified as boundary rule 9 in `docs/spec/contracts/privacy-data-boundaries.md`: no in-app surface may claim "nothing is sent" / "stays on this device" while rows 2–6 or 15 can fire, so the in-app copy is reconciled to be truthful (closes deviation DH5). A TestFlight/Play build must not ship until the labels reflect those rows. Execution tracked in rrradio-ios#80 (store-label authoring, copy reconciliation, proxy-retention confirmation, optional privacy-manifest version field).

## Catalog quality loop (2026-09-03) → ADR 002

The weekly `catalog-watch` sweep failed 12 of its last 15 runs and its one success took 3 h to produce an unmerged 135k-line PR, so `station-health.json` on `main` sat frozen at 2026-06-15 on every facet and nothing consumed it. **Decision: split measure / decide / act / report into small idempotent stages, and move the health data out of the source tree.** `station-probe.yml` runs daily at 05:00 UTC: `plan-probe` picks the day's targets (curated tier + play-weighted hot set daily, 1/7 of the long tail on rotation), a shard matrix probes them with a 25 min per-shard budget writing append-only NDJSON observation rows, a merge job appends those to the orphan **`health-data`** branch and runs `derive-health` to fold them into the record, and Mondays `health-digest` refreshes one `catalog-quality` issue. `deploy.yml` overlays `station-health.json` from `health-data` into `dist/`, so the tracker's URL is unchanged. Three things make it stick: bad stations are *data*, never a job failure (only `plan`/`merge` failing is red — `--strict` is never passed in CI); health artifacts never go through branch protection, which is what killed every push before; and bad verdicts carry a hard/soft class plus a persisted streak, so phase 2 can flip a status on evidence rather than on one 8 s timeout. `catalog-watch.yml` becomes a dispatch-only Radio Browser refresh. Full contracts: `design/decisions/002-catalog-quality-loop.md`, `docs/station-health.md`.
