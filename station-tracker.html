How dedupe works · the identity model & signal ladder

Two stations can look like duplicates for very different reasons. We sort every pair into one of three buckets — the rule that decides whether a row gets merged away, flagged, or left alone.

FEED
Delivery / bitrate / codec / protocol variants of one audio stream (e.g. Bayern 1 Oberbayern (HLS 96) vs (HLS 192)). These are true duplicates → collapsed to one canonical row.
FAMILY
Regional or sub-brand siblings of one brand (Bayern 1 Oberbayern / Franken / Schwaben; bigFM's genre channels). Genuinely different programmes → kept distinct, just tagged with a family chip so a curator reads them as one group, not noise.
DISTINCT
Everything else — unrelated stations, left untouched.

To collapse FEEDs we compare each pair through a ladder of signals, strongest first — the first one that matches (and isn't blocked by a guard) wins:

  1. stationuuid — same curated catalog record.
  2. exact stream URL — byte-identical endpoint (proxy wrappers like worldradio.online/proxy/?q=… are unwrapped to the real inner URL first).
  3. stream fingerprint — host + path with bitrate / codec / packaging tokens stripped, so the same feed at different qualities on one CDN path collapses. Guarded by a channel-number check so SRF 3 never fuses into SRF 4 News via a shared CDN path.
  4. name + broadcaster — order-independent, noise-stripped name signature within one homepage host.
  5. family tag — the FAMILY layer above; flags siblings, never merges them.

When a FEED group collapses, the canonical row is picked quality-first: best bitrate, then codec (AAC > MP3 > HLS), then RB votes / clicks. A curator can force a merge the signals miss (or block a wrong one) via data/sources/radio-browser/overrides.yaml.

Implemented in tools/dedupe-raw.mjs (this RB candidate pool), tools/check-duplicates.mjs (the curated-catalog gate), and tools/lib/station-family.mjs (family detection) — all sharing tools/lib/dedupe-normalize.mjs + station-name-signature.mjs.
